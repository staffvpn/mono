# TEYDO

Площадка задач: заказчик описывает, что нужно сделать, исполнитель берётся и делает.
Один продукт в трёх видах — адаптивный сайт, Telegram Mini App и админ-панель.

> **Статус: рабочая сборка на моках.** Интерфейс, логика ролей, сделки, споров и
> админки написаны полностью. Внешние сервисы — база данных, платежи, SMS — **не подключены**.
> Что именно работает по-настоящему, а что через мок, перечислено ниже в разделе
> [«Что работает на самом деле»](#что-работает-на-самом-деле).

---

## Стек

| Слой | Что используется |
|---|---|
| Фреймворк | Next.js 16 (App Router), React 19 |
| Язык | TypeScript 5.7, strict |
| Стили | Tailwind CSS 3.4 + CSS-переменные для токенов темы |
| Данные | слой сервисов; сейчас за ним мок-хранилище в `localStorage` |
| Серверная часть | route handlers Next.js в `src/app/api` (Node.js runtime) |

Сторонних UI-библиотек нет: компоненты в `src/components/ui` написаны под проект.

## Установка и запуск

```bash
npm install
cp .env.example .env      # заполнить при подключении Telegram
npm run dev               # http://localhost:3000
```

Прочие команды:

```bash
npm run build       # production-сборка
npm run start       # запуск собранного приложения
npm run typecheck   # tsc --noEmit
```

Node.js 20.9+ (на Vercel сейчас 24.x).

## Переменные окружения

Полный список с пояснениями — в [`.env.example`](.env.example).

### Клиентские (попадают в браузер, секретов быть не должно)

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `NEXT_PUBLIC_USE_MOCK_DATA` | `true` | `true` — данные из мок-хранилища; `false` — сервисы уходят по HTTP |
| `NEXT_PUBLIC_API_URL` | `/api` | база API; пусто = свои маршруты того же домена |
| `NEXT_PUBLIC_TELEGRAM_BOT_USERNAME` | `teydobot` | имя бота без `@` для ссылок `t.me` и Login Widget |

### Серверные (в браузер не попадают)

| Переменная | Обязательна | Зачем |
|---|---|---|
| `BOT_TOKEN` | для входа через Telegram | токен из @BotFather; проверка подписи `initData` |
| `SESSION_SECRET` | для любого входа | подпись сессионной куки, минимум 16 символов |
| `SMS_PROVIDER`, `SMS_API_KEY` | для входа по телефону | пока пусты — вход по номеру отключён |
| `PAYMENT_PROVIDER`, `PAYMENT_SHOP_ID`, `PAYMENT_SECRET_KEY` | для реальных платежей | пока пусты — оплата демонстрационная |
| `DATABASE_URL` | для постоянного хранения | пока пусто — данные живут в браузере |

**Секреты никогда не пишутся в код и не начинаются с `NEXT_PUBLIC_`.**
`SESSION_SECRET` генерируется так:

```bash
openssl rand -hex 32
```

## Режим моков

`NEXT_PUBLIC_USE_MOCK_DATA=true` (по умолчанию) означает:

* весь слой данных обслуживает `src/services/store.ts` — объект в памяти, зеркалящийся
  в `localStorage` под ключом `teydo.mock.v1`;
* демонстрационные записи лежат **только** в `src/mock/data.ts` и больше нигде;
* интерфейс честно показывает плашку «Демо-режим: backend не подключён»;
* платёж считается зарезервированным локально — денег никто не списывает.

Сброс данных: `localStorage.removeItem('teydo.mock.v1')` в консоли браузера
или кнопка сброса в админ-панели.

Переключение на настоящий backend — это `NEXT_PUBLIC_USE_MOCK_DATA=false` и
`NEXT_PUBLIC_API_URL`. Модули в `src/services/*` уже разделены на «интерфейс» и
«мок-реализация»: HTTP-ветка в каждом из них подписана комментарием.

## Telegram

Подробная инструкция — в [TELEGRAM.md](TELEGRAM.md). Коротко:

1. В @BotFather создать бота, получить токен, положить его в `BOT_TOKEN` на хостинге.
2. `/setdomain` — указать домен сайта (нужно для Login Widget).
3. `/newapp` — создать Mini App и указать URL приложения.
4. Проверить вход: приложение отправляет `initData` на `POST /api/auth/telegram`,
   сервер пересчитывает подпись и только после этого признаёт пользователя.

**Данные из `window.Telegram.WebApp.initDataUnsafe` используются только для отрисовки
до ответа сервера и никогда — для решения о доступе.** Подпись Mini App и подпись
Login Widget считаются по-разному:

| Источник | Секрет для HMAC |
|---|---|
| Mini App (`initData`) | `HMAC_SHA256(bot_token, "WebAppData")` |
| Login Widget (объект с `hash`) | `SHA256(bot_token)` |

Обе реализованы в `src/server/telegram.ts` со сравнением за постоянное время и
проверкой свежести (24 часа).

## Что работает на самом деле

### Работает по-настоящему

* Весь интерфейс: публичные страницы, приложение, админ-панель, светлая и тёмная тема,
  адаптив от 320 px, режим Telegram Mini App (fullscreen, safe-area, BackButton, haptic).
* Проверка подписи Telegram на сервере — чистая криптография, ничего не требует, кроме `BOT_TOKEN`.
* Выдача и чтение подписанной httpOnly-сессии (`SESSION_SECRET`).
* Разбор текста задачи на поля (категория, дата, время, срочность, бюджет) — набор правил,
  а не ИИ; флаг `AI_TASK_CREATION` выключен, и интерфейс нигде не называет это искусственным интеллектом.
* Подбор исполнителей и задач: детерминированный расчёт совпадения с человеческим объяснением.
* Ролевая модель админки (OWNER / SUPER_ADMIN / MODERATOR / SUPPORT / FINANCE / ANALYST),
  журнал действий, обязательная причина для опасных операций, мягкое удаление.

### Работает через мок

* Хранение пользователей, задач, откликов, заказов, чатов, отзывов, уведомлений —
  `localStorage` одного браузера. Другой браузер этих данных не увидит.
* Платежи: экран оплаты со способами (карта, СБП, Telegram), резерв, перевод и возврат
  меняют статус в мок-хранилище. **Списаний нет.** Оплата «наличными» и «переводом на карту»
  из продукта убрана намеренно: вне площадки не работают ни резерв, ни возврат, ни спор.
* Кошелёк: баланс, резерв по активным заказам, история операций и заявка на вывод.
  Баланс считается из платежей и выплат, а не хранится числом.
* Отправка СМС: провайдер не подключён, `/api/auth/phone/*` возвращает 501.
* Push- и Telegram-уведомления: показываются внутри приложения, наружу не отправляются.
* Проверка документов: очередь и статусы есть, реальной проверки нет.
* Аналитика в админке считается по мок-данным.

### Не работает и об этом сказано в интерфейсе

* Реальные списания и выплаты.
* Отправка сообщений в Telegram от имени бота.
* Хранение данных между устройствами.

## Что нужно подключить перед запуском

1. **База данных.** Схема — в [docs/DATABASE.md](docs/DATABASE.md). После её появления
   `src/services/store.ts` удаляется целиком, а сервисы переключаются на HTTP.
2. **Платёжный провайдер** с поддержкой холдирования и разделения выплат
   (в РФ это, например, ЮKassa / CloudPayments / Тинькофф Касса; для маркетплейса
   нужен договор на приём платежей в пользу третьих лиц). Точка подключения —
   интерфейс `PaymentProvider` в `src/services/catalog.ts`.
3. **SMS-провайдер** (например, SMS.ru, SMSC, Twilio) — интерфейс `SmsProvider`
   в `src/server/sms.ts`. Хранилище кодов из памяти процесса заменить на Redis
   или таблицу: в serverless память не переживает следующий запрос.
4. **Хранилище файлов** для фото задач, портфолио и материалов споров (S3-совместимое).
5. **Отправка уведомлений в Telegram** через Bot API от `BOT_TOKEN`.
6. **Юридические документы.** Тексты в `/legal` — рабочая редакция, помеченная как
   черновик. Их обязан проверить юрист до запуска.

## Деплой

Проект рассчитан на Vercel:

1. Импортировать репозиторий, фреймворк определится как Next.js.
2. В Settings → Environment Variables добавить `BOT_TOKEN` и `SESSION_SECRET`
   (и остальные — по мере подключения).
3. Задеплоить и указать полученный домен в @BotFather (`/setdomain`, `/newapp`).

Заголовки безопасности и `frame-ancestors` для Telegram Web заданы в `vercel.json`.

## Правила проекта

* Никакой выдуманной статистики, отзывов, пользователей, платежей и проверок.
  Нет данных — пишем «нет данных», а не ноль.
* Ни одна интеграция не объявляется работающей, пока она не подключена.
* Секреты только на сервере. Идентификатор пользователя, цена и статус платежа,
  пришедшие от клиента, доверенными не считаются.
* Бесплатно: создание задачи, поиск, отклик, переписка, отзывы.
  Платформа зарабатывает комиссию только с успешной сделки.
